# Асаны: истоки

Статический сайт для изучения того, как асаны описаны в первоисточниках.
Слева — список асан трактата, справа — текст этого трактата об асане:
деванагари, IAST, кириллическая транслитерация, пословный разбор, буквальный
и литературный перевод, примечания к чтениям.

В собрании два памятника:

* **Ахирбудхнья-самхита, XXXI глава** — одиннадцать главных асан;
* **Васишт̣ха-сам̣хитā, Йога-кāн̣д̣а, гл. 1, ст. 67–82** — десять асан, каждая
  разобрана по стихам.

Трактат выбирается в списке слева сверху. Десять асан Васишт̣ха-сам̣хиты
совпадают по ключам с асанами Ахирбудхнья-самхиты, поэтому страница асаны
показывает описания из обоих памятников подряд, каждое — со своей датировкой.
Асана, которая есть только в одном трактате (Чакрасана), в списке приглушена,
когда выбран другой.

Тексты приведены дословно по источникам, без добавлений и реконструкций.

## Что где лежит

```
index.html                  единственная страница (хеш-роутинг)
assets/style.css            оформление
assets/app.js               загрузка данных, навигация, рендер
data/treatises.json         индекс трактатов и общие подписи сайта
data/ahirbudhnya-samhita.json   данные трактата (генерируются из PDF)
data/vasishtha-samhita.json     данные второго трактата (тоже из PDF)
sources/*.pdf               исходные PDF (русский и английский)
tools/extract.py            сборка JSON Ахирбудхнья-самхиты
tools/extract_vasishtha.py  сборка JSON Васишт̣ха-сам̣хиты
tools/common.py             общие разборщики PDF (блоки, строки, таблицы)
tools/translit.py           карта транслитерации IAST → кириллица
tools/sanskrit.py           знаки у санскритских слов в русском тексте
```

## Локальный просмотр

Открывать `index.html` двойным щелчком нельзя: браузер не отдаст JSON через
`file://`. Нужен любой статический сервер:

```bash
python3 -m http.server 8080
# затем http://localhost:8080
```

## Как данные получаются из PDF

`data/ahirbudhnya-samhita.json` не набирался руками. Скрипт читает PDF из
`sources/`, разбирает его на структурные блоки (стихи, пословный разбор,
переводы, примечания) и складывает в JSON. Формулировки при этом копируются
символами исходника.

```bash
pip install pymupdf
cd tools
python3 extract.py ../data/ahirbudhnya-samhita.json
python3 extract_vasishtha.py ../data/vasishtha-samhita.json
```

Второй скрипт устроен сложнее: в PDF Васишт̣ха-сам̣хиты есть заголовки двух
уровней, вложенные списки, таблица датировок, английские цитаты с русским
переводом и разрывы абзацев через границу страницы. Он собирает всё это в
блоки (`h2`, `h3`, `h4`, `p`, `list`, `quote`, `table`), не меняя текст.

Пословный разбор в русском издании Ахирбудхнйа-сам̣хиты напечатан латиницей
(IAST), поэтому скрипт переписывает термины кириллицей по одной карте
(`tools/translit.py`) — с точкой **под** «м»: `ṃ`/`ṁ` → `м̣`, `ṛ` → `р̣`,
`ṝ` → `р̣̄`, `ḷ` → `л̣`, `ś` → `ш́`, `ṣ` → `ш`, `ṇ` → `н̣`, `ṭ` → `т̣`,
`ḍ` → `д̣`, `ñ` → `н̃`, `ṅ` → `н̇`, `ḥ` → `х̣`, `ā` остаётся латинской.
В английской версии термины остаются латиницей с диакритикой, как в PDF.
Строки «кириллической транслитерации» стихов из более старого PDF (там точка
стояла над «м») приводятся к той же карте — меняется только знак над буквой,
сами строки и разбивка на строки не трогаются.
Проверить соответствие схемы можно так:

```bash
cd tools && python3 translit.py
# verse lines reproduced from the printed transliteration: 23 / 28
```

Расхождения в пяти строках — это места, где сама печатная транслитерация
отличается от строки IAST (другое чтение, редакторские скобки), а не ошибки
таблицы.

В конце работы скрипт печатает проверку: какие строки PDF не попали в JSON.
Сейчас в отчёте остаются только заголовки разделов — они хранятся в данных
отдельно (как названия асан, номера стихов и подзаголовки), а не как текст
абзацев.

## Знаки у каждого санскритского слова

Печатные издания ставят знаки непоследовательно: в одном месте «āсана», в другом
«асана», а в колонтитулах Ахирбудхнйа-сам̣хиты названия асан напечатаны вовсе без
знаков («Майурасана»). Сайт показывает одно написание: у санскритского слова
стоят те знаки, которые нужны по карте транслитерации. Скрипт `tools/sanskrit.py`
делает это для русских подписей, названий асан, перечней, пословного разбора и
прозаических разделов; английская версия и строки стихов не трогаются — там
текст уже напечатан с диакритикой.

Скрипт только добавляет знаки: ни одна буква не вставляется, не убирается и не
переставляется. Общие подписи сайта («Āсаны», «Найти āсану», «Пāн̃чарāтра»)
правятся вручную в `index.html`, `assets/app.js` и `data/treatises.json`.
Проверка — тем же скриптом, он печатает список мест, где знаки ещё не стоят:

```bash
cd tools && python3 sanskrit.py
# strings that would change: 0
```

## Диакритика в кириллице

Знаков «м с точкой снизу» и подобных в большинстве шрифтов нет, поэтому браузер
подставлял для таких букв другой шрифт: буква выглядела жирнее соседних, а
межбуквенный интервал (`letter-spacing`) сдвигал точку в сторону. Теперь знак
рисуется средствами CSS (`.mk` в `assets/style.css`) прямо над/под буквой, а
настоящий комбинируемый символ остаётся в тексте с нулевым кеглем — поэтому
копирование, поиск по странице и скринридеры получают правильную букву.

## Кеш GitHub Pages

Pages отдаёт файлы с `Cache-Control: max-age=600`, поэтому браузер может
показывать старые `app.js` и JSON. От этого стоят параметры версии: `?v=` у
`assets/style.css` и `assets/app.js` в `index.html` и константа `BUILD` в
`assets/app.js` (ею помечаются запросы к данным). После правок увеличьте обе —
читатель сразу получит новую версию, а текущая сборка видна в подписи под
страницей асаны («версия …»).

## Датировка

Страница асаны идёт сплошным текстом: название асаны, затем — по каждому
трактату — название источника с номером главы, сразу под ним краткая датировка
(век или год, кто датирует и работа, на которую опирается дата), дальше сам
текст. Ничего не спрятано в раскрывающиеся блоки, кроме самой статьи о
датировке. Кнопка «Читать датировку
полностью» раскрывает весь раздел о датировке — дословно, как в источнике.
Краткие строки лежат в `data/treatises.json` (`datingSummary`), полный текст —
в `data/<трактат>.json` в поле `dating` (собирается из PDF автоматически), и он
же остаётся в статье на странице «О трактате».

## Как добавить третий трактат

1. Положить PDF (или транслитерацию) в `sources/`.
2. Собрать по той же схеме JSON: `poses[]` с полями
   `key`, `iast`, `number`, `name{ru,en}`, `gloss{ru,en}`, `verses{ru,en}`,
   `text{ru:[…], en:[…]}`; блоки текста бывают типов `verse_card`
   (`verses`, `sections[]` из `verse` с `lines`), `verse` (`lines`),
   `words` (`groups` — список разборов по стихам, каждый — пары
   `[термин, значение]`), `prose` / `note` (`paragraphs`), `subhead`.
   Блоки статьи о трактате и раздела о датировке — это `title`, `h2`, `h3`,
   `h4`, `p`, `list` (`items` — строки или `{html, level}`), `quote`
   (`paragraphs`), `table` (`rows`). Поле `html` содержит разметку курсива и
   жирного, взятую из PDF.
   Ключ `key` общий для всех трактатов: именно по нему асана одной школы
   сопоставляется с асаной другой. Если в трактате есть асана, которой нет в
   списке, просто добавьте её `key` — она появится в списке этого трактата.
3. Добавить запись в `data/treatises.json` (id, file, название, традиция,
   издание, переводчик, ссылка на PDF, при наличии — `datingSummary` с полями
   `note`, `label` (подпись последнего столбца) и `items[]` (`who`, `when`,
   `whenNote`, `work`)). Если `datingSummary` записан в самом JSON трактата, он
   имеет приоритет над записью в индексе — так краткая датировка собирается из
   таблицы PDF без ручного набора.

Когда одна и та же асана есть в нескольких трактатах, её страница показывает
описания по каждому трактату подряд, с заголовком источника.

## Публикация на GitHub Pages

Сайт статический, сборка не нужна. В настройках репозитория:
**Settings → Pages → Build and deployment → Deploy from a branch →
branch `main`, folder `/ (root)`**. Файл `.nojekyll` уже добавлен, поэтому
Jekyll не будет мешать отдавать `data/*.json`.
