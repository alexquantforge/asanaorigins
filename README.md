# Асаны: истоки

Статический сайт для изучения того, как асаны описаны в первоисточниках.
Слева — список асан трактата, справа — текст этого трактата об асане:
деванагари, IAST, кириллическая транслитерация, пословный разбор, буквальный
и литературный перевод, примечания к чтениям.

В собрании два памятника:

* **Ахирбудхнья-самхита, XXXI глава** — одиннадцать главных асан;
* **Васишт̣ха-сам̣хитā, Йога-кāн̣д̣а, гл. 1, ст. 67–82** — десять асан, каждая
  разобрана по стихам.

Трактат выбирается в списке слева сверху. Десять асан Васишт̣ха-сам̣хиты
совпадают по ключам с асанами Ахирбудхнья-самхиты, поэтому страница асаны
показывает описания из обоих памятников подряд, каждое — со своей датировкой.
Асана, которая есть только в одном трактате (Чакрасана), в списке приглушена,
когда выбран другой.

Тексты приведены дословно по источникам, без добавлений и реконструкций.

## Локальный просмотр

Открывать `index.html` двойным щелчком нельзя: браузер не отдаст JSON через
`file://`. Нужен любой статический сервер:

```bash
python3 -m http.server 8080
# затем http://localhost:8080
```

## Как данные получаются из PDF

`data/ahirbudhnya-samhita.json` не набирался руками. Скрипт читает PDF из
`sources/`, разбирает его на структурные блоки (стихи, пословный разбор,
переводы, примечания) и складывает в JSON. Формулировки при этом копируются
символами исходника.

```bash
pip install pymupdf
cd tools
python3 extract.py ../data/ahirbudhnya-samhita.json
python3 extract_vasishtha.py ../data/vasishtha-samhita.json
```

Второй скрипт устроен сложнее: в PDF Васишт̣ха-сам̣хиты есть заголовки двух
уровней, вложенные списки, таблица датировок, английские цитаты с русским
переводом и разрывы абзацев через границу страницы. Он собирает всё это в
блоки (`h2`, `h3`, `h4`, `p`, `list`, `quote`, `table`), не меняя текст.

Пословный разбор в русском издании Ахирбудхнйа-сам̣хиты напечатан латиницей
(IAST), поэтому скрипт переписывает термины кириллицей по одной карте
(`tools/translit.py`) — с точкой **под** «м»: `ṃ`/`ṁ` → `м̣`, `ṛ` → `р̣`,
`ṝ` → `р̣̄`, `ḷ` → `л̣`, `ś` → `ш́`, `ṣ` → `ш`, `ṇ` → `н̣`, `ṭ` → `т̣`,
`ḍ` → `д̣`, `ñ` → `н̃`, `ṅ` → `н̇`, `ḥ` → `х̣`, `ā` остаётся латинской.
В английской версии термины остаются латиницей с диакритикой, как в PDF.
Строки «кириллической транслитерации» стихов из более старого PDF (там точка
стояла над «м») приводятся к той же карте — меняется только знак над буквой,
сами строки и разбивка на строки не трогаются.
Проверить соответствие схемы можно так:

```bash
cd tools && python3 translit.py
# verse lines reproduced from the printed transliteration: 23 / 28
```

Расхождения в пяти строках — это места, где сама печатная транслитерация
отличается от строки IAST (другое чтение, редакторские скобки), а не ошибки
таблицы.

В конце работы скрипт печатает проверку: какие строки PDF не попали в JSON.
Сейчас в отчёте остаются только заголовки разделов — они хранятся в данных
отдельно (как названия асан, номера стихов и подзаголовки), а не как текст
абзацев.

## Знаки у каждого санскритского слова

Печатные издания ставят знаки непоследовательно: в одном месте «āсана», в другом
«асана», а в колонтитулах Ахирбудхнйа-сам̣хиты названия асан напечатаны вовсе без
знаков («Майурасана»). Сайт показывает одно написание: у санскритского слова
стоят те знаки, которые нужны по карте транслитерации. Скрипт `tools/sanskrit.py`
делает это для русских подписей, названий асан, перечней, пословного разбора и
прозаических разделов; английская версия и строки стихов не трогаются — там
текст уже напечатан с диакритикой.

Скрипт только добавляет знаки: ни одна буква не вставляется, не убирается и не
переставляется. Общие подписи сайта («Āсаны», «Найти āсану», «Пāн̃чарāтра»)
правятся вручную в `index.html`, `assets/app.js` и `data/treatises.json`.
Проверка — тем же скриптом, он печатает список мест, где знаки ещё не стоят:

```bash
cd tools && python3 sanskrit.py
# strings that would change: 0
```

## Имена исследователей

Краткие строки датировки под названием асаны — это собственный конспект сайта:
кто предлагает дату и на чём основывается. В русском томе Ахирбудхнйа-сам̣хиты
имена уже стоят по-русски («Ф. Отто Шрадер», «Д. Вьюстик», «Марион Растелли»),
а таблица в томе Васишт̣ха-сам̣хиты называет работы по латинским ключам
библиографии. Чтобы одна и та же колонка не читалась двумя способами,
`tools/authors.py` даёт русское написание фамилий — ровно в том виде, в каком
эти фамилии пишет русский текст тех же изданий («Бёрч», «Буи», «Маллинсон и
Синглтон», «Вьюстик», «Кола́» — с ударением, как в издании).

Меняются только фамилии. Годы, названия работ, цитаты («as shown below»,
«Chronology») и подписи разделов остаются как напечатано, потому что это
цитаты. Полная статья о датировке — дословная, её скрипт не трогает.

```bash
cd tools && python3 authors.py
# strings that would change: 0
```

## Диакритика в кириллице

Знаков «м с точкой снизу» и подобных в большинстве шрифтов нет, поэтому браузер
подставлял для таких букв другой шрифт: буква выглядела жирнее соседних, а
межбуквенный интервал (`letter-spacing`) сдвигал точку в сторону. Поэтому знак
рисуется средствами CSS (`.mk` в `assets/style.css`) прямо над/под буквой, а
настоящий комбинируемый символ остаётся в тексте с нулевым кеглем — благодаря
этому копирование, поиск по странице и скринридеры получают правильную букву.

Знак отсчитывается **от базовой линии**, а не от низа строки: `.mk` —
`inline-block` высотой `1em` с `line-height: 1`, поэтому низ его бокса стоит
ниже базовой линии на постоянную величину шрифта, а не на высоту строки. Раньше
отсчёт шёл от низа строки, и в тексте с `line-height: 1.7` (это основной текст
сайта) черта долготы ложилась поперёк буквы: «а̄» выглядела как перечёркнутая
«а». Расстояние до знака задано в `ex` — в высоте строчной буквы, — потому что у
Cormorant Garamond она меньше, чем у Spectral. У прописных (`is-cap`) знак идёт
над верхом заглавной буквы.

Все точки снизу стоят на одной высоте: `м̣`, `н̣`, `т̣`, `х̣`, `д̣`, `л̣`, `ш̣`,
`к̣`, `с̣` — одна и та же линия в любом начертании и кегле. Исключение одно:
у «р» хвост уходит вниз ровно под точкой, поэтому `р̣` опускается под хвост.
У «д» ножки стоят по краям, а под точкой в середине буквы пусто — раньше её
точка тоже опускалась (по ошибке, «на всякий случай») и выглядела ниже, чем у
«н»; теперь она на общей линии.

## Шрифты

Шрифты лежат в `assets/fonts` (`Spectral`, `Cormorant Garamond`,
`Noto Serif Devanagari`), по одному файлу woff2 на начертание, лицензия OFL —
рядом, в тех же каталогах. Сборка:

```bash
npm i @expo-google-fonts/spectral @expo-google-fonts/cormorant-garamond \
      @fontsource/noto-serif-devanagari
python3 tools/build_fonts.py --src node_modules
```

Свои файлы нужны не ради скорости, а ради диакритики. Google Fonts отдаёт шрифт
нарезанным по `unicode-range`: кириллическая «а» лежит в кириллическом наборе, а
знак долготы `U+0304` — только в latin-ext. Браузер берёт букву из одного файла,
знак из другого, склеить их по GPOS уже нельзя, и знак садится не над буквой.
Кроме того, в Spectral и Cormorant Garamond у части кириллических букв (м, н, ш,
р, т, д, в, х) нет якорей mark-to-base, поэтому знаки всё равно рисует CSS.
Сборка берёт полные файлы и режет их сама, сохраняя таблицы GPOS
(`--layout-features=*`).

## Кеш GitHub Pages

Pages отдаёт файлы с `Cache-Control: max-age=600`, поэтому браузер может
показывать старые `app.js` и JSON. От этого стоят параметры версии: `?v=` у
`assets/style.css` и `assets/app.js` в `index.html` и константа `BUILD` в
`assets/app.js` (ею помечаются запросы к данным). После правок увеличьте обе —
читатель сразу получит новую версию, а текущая сборка видна в подписи под
страницей асаны («версия …»).

## Датировка

Страница асаны идёт сплошным текстом: название асаны, затем — по каждому
трактату — название источника с номером главы, сразу под ним краткая датировка
(век или год, кто датирует и работа, на которую опирается дата), дальше сам
текст. Ничего не спрятано в раскрывающиеся блоки, кроме самой статьи о
датировке. Кнопка «Читать датировку
полностью» раскрывает весь раздел о датировке — дословно, как в источнике.
Краткие строки лежат в `data/treatises.json` (`datingSummary`), полный текст —
в `data/<трактат>.json` в поле `dating` (собирается из PDF автоматически), и он
же остаётся в статье на странице «О трактате».

## Номера глав — арабскими цифрами

Источники нумеруют главы то римскими, то арабскими цифрами: в одном трактате
«XXXI глава», в другом «глава 1», в третьем «улласа IX», а в английском томе
«chapter XXXI». Сайт везде показывает одно и то же — арабские цифры.

Этим занят `tools/numeral.py`: все три сборщика вызывают его на готовом JSON
(`numeral.fix_document(data)`), поэтому в `data/*.json` римских номеров глав уже
нет, а поле `chapter` записано как `"31"`, `"1"`, `"9"`.

Правило узкое, чтобы не пострадал ни один другой номер:

* меняется только то число, которое стоит рядом со словом «глава» (`глава
  XXXI`, `XXXI глава`, `гл. I`, `chapter XXXI`, `ch. I`, `ullāsa IX`,
  `улласа IX`), и ссылка вида «глава.стих» (`IX.24` → `9.24`);
* века (`XII–XIII века`), тома (`т. II`), шифры и каталожные номера (`Oudh
  VIII, 24`), перечни в тексте (`I. Текст…`, `II. Комментарий…`) остаются как
  напечатано: это не номера глав;
* ссылка «глава.стих» переводится и тогда, когда её глава совпадает по числу с
  главой трактата (`I.33` Йога-сӯтры в томе Васишт̣ха-сам̣хиты); меняется только
  запись числа, само число и его смысл — нет;
* значение числа не меняется никогда: XXXI — это 31 и остаётся 31, ни одно
  слово не добавлено, не убрано и не переставлено.

Проверка: `python3 tools/numeral.py` печатает контрольные строки до и после;
`python3 tools/numeral.py data/*.json` конвертирует уже собранные файлы (после
этого изменений быть не должно — иначе пересоберите JSON).

## Как добавить третий трактат

1. Положить PDF (или транслитерацию) в `sources/`.
2. Собрать по той же схеме JSON: `poses[]` с полями
   `key`, `iast`, `number`, `name{ru,en}`, `gloss{ru,en}`, `verses{ru,en}`,
   `text{ru:[…], en:[…]}`; блоки текста бывают типов `verse_card`
   (`verses`, `sections[]` из `verse` с `lines`), `verse` (`lines`),
   `words` (`groups` — список разборов по стихам, каждый — пары
   `[термин, значение]`), `prose` / `note` (`paragraphs`), `subhead`.
   Блоки статьи о трактате и раздела о датировке — это `title`, `h2`, `h3`,
   `h4`, `p`, `list` (`items` — строки или `{html, level}`), `quote`
   (`paragraphs`), `table` (`rows`). Поле `html` содержит разметку курсива и
   жирного, взятую из PDF.
   Ключ `key` общий для всех трактатов: именно по нему асана одной школы
   сопоставляется с асаной другой. Если в трактате есть асана, которой нет в
   списке, просто добавьте её `key` — она появится в списке этого трактата.
3. Добавить запись в `data/treatises.json` (id, file, название, традиция,
   издание, переводчик, ссылка на PDF, при наличии — `datingSummary` с полями
   `note`, `label` (подпись последнего столбца) и `items[]` (`who`, `when`,
   `whenNote`, `work`)). Если `datingSummary` записан в самом JSON трактата, он
   имеет приоритет над записью в индексе — так краткая датировка собирается из
   таблицы PDF без ручного набора.

Когда одна и та же асана есть в нескольких трактатах, её страница показывает
описания по каждому трактату подряд, с заголовком источника.

## Третий трактат: «Ма̄насолла̄са»

`tools/extract_manasollasa.py` собирает `data/manasollasa.json` из двух PDF
(русского и английского). Устроен он иначе, чем первые два:

* асаны здесь не описаны, а только названы в стихах 24–26 девятой уллы, и
  страница позы собрана в том же порядке, что и в первых двух трактатах:
  **стих** (девана̄гарӣ, IAST, кириллица — по одному блоку на строку стиха,
  с номером стиха над карточкой), **пословный разбор**, **буквальный
  перевод**, **литературный перевод**, затем **классификация по божествам**
  из §6.3 с цитатой девана̄гарӣ;
* пословного разбора в самой справке нет, поэтому он собран из её же слов:
  в `WORDS` каждое слово стиха (разделённое так, как это делает сама справка
  в §6.5) получает ровно тот перевод, который стоит на его месте в переводе
  §6.2; `check_words()` не даёт собрать страницы, если слово не совпало с
  текстом стиха или перевода — то есть ничего не дописано;
* «буквальный перевод» — перевод самой справки (§6.2), «литературный» —
  перевод изд. 1978 г., приведённый в справке дословно, с указанием
  страницы под ним;
* весь остальной текст справки (§0–§5, §6.1, §6.4–§10) лежит в поле `about`,
  §2 (датировка) — в поле `dating`, краткие строки датировки собираются из
  таблицы §2.4;
* в блоках появились два новых типа: `deva` (`lines` — строки девана̄гарӣ) и
  `code` (`text` — пример из §8); нумерованный список — это `list` с
  `ordered: true` и `start`, вложенный в пункт пример кода — поле `code`
  у пункта.

Девана̄гарӣ в этих PDF набрана шрифтом с испорченной таблицей символов: часть
глифов на границах фрагментов выходит латиницей или служебными знаками
(`स्वस्ति\x0f\x10कं`, `वार्त्तिÚKक`). `clean_runs()` убирает только такие
посторонние знаки — ни одна буква девана̄гарӣ не сдвигается и не удаляется.
Скрипт печатает всё, что убрал, вместе с контекстом, чтобы это можно было
сверить построчно.

## Диакритика в английском томе

Английский PDF печатает санскрит упрощённой латиницей английских книг
(`Shankara`, `Sureshvara`, `Manasollasa`, `Dakshinamurti-stotra`), а сайт
показывает IAST в обоих языках. Поэтому `tools/iast.py` переписывает
английский том перед выкладкой: `extract_manasollasa.py` вызывает
`iast_lib.fix_tree()` для `lang == "en"` — и для статьи, и для страниц асан.

Правила простые:

* меняются только те буквы, которых требует санскритская орфография
  (`sh` → `ś`/`ṣ`, `n` → `ṇ`, `t`/`d` → `ṭ`/`ḍ`, `a`/`i`/`u` → `ā`/`ī`/`ū`,
  `m` перед согласной → `ṃ`, `ch` → `c`); ни одно слово не добавляется и не
  переставляется — это карта целых слов (`MAP`), а не замена по буквам;
* адреса, имена файлов, шифры и `key`/`number`/`pdf` не трогаются совсем:
  `archive.org/details/…Sureshwaracharya…` остаётся как напечатано;
* санскритские названия мест пишутся с диакритикой (`Vārāṇasī`, `Śṛṅgeri`,
  `Kāñcī`, `Dvārakā`), а английские формы современных топонимов, названия
  учреждений и фамилии современных исследователей остаются как в источнике
  (`Mysore`, `Madras`, `Ramtek`, `Jammu`, `Aufrecht`, `Thrasher`, `Dasgupta`,
  `Kashi Hindu University`);
* два пункта §0, где справка сама описывала упрощённую запись, переписаны
  (`CONVENTIONS_EN`): теперь они описывают то, что сайт действительно делает.

Проверка: `python3 tools/iast.py` печатает контрольные строки; после правки
карты пересоберите JSON (`python3 extract_manasollasa.py ../data/manasollasa.json`
из `tools/`) — русский том не зависит от этой карты и остаётся дословным.

## Публикация на GitHub Pages

Сайт статический, сборка не нужна. В настройках репозитория:
**Settings → Pages → Build and deployment → Deploy from a branch →
branch `main`, folder `/ (root)`**. Файл `.nojekyll` уже добавлен, поэтому
Jekyll не будет мешать отдавать `data/*.json`.
